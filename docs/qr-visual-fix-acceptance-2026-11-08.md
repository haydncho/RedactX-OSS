# 二维码误框与视觉类别修复：测试环境验收

日期：2026-11-08。基于正式版 0.3.0，分支 `codex/qr-visual-class-fix`。
本次仅部署独立测试环境，未升级线上应用、介绍站或 drg-oras。

## 根因与修复

1. OpenCV 在合成样例中将正文区域识别为二维码候选。原逻辑仅对单码候选校验尺寸、长宽比，没有核验定位图案，多码候选则直接接受。现在统一检查三个角部的嵌套方形定位图案；不要求解出内容，因此保留对部分内容损坏二维码的检测。多码检测保留原有大尺寸二维码支持。
2. 上游类别映射与其固定版本模型卡一致，但模型将样例圆章输出为签名。原适配器逐类接受超过阈值的分数，同一区域可以产生两个类别；去重也仅限同类。现在每个 query 取四类中的最高分，复选框最高时不作为印章或签名输出；高度重合的跨类框去重，中等重合的不同对象保留。
3. 对模型已检出的区域，以闭合椭圆外环、内环和中间空隙的像素覆盖作为双环章的正向证据，纠正红色、灰色圆章类别；同一章边缘被分块识别成签名的弧段归并为印章。没有形状证据时保留模型类别，不按颜色或宽高比直接猜测。
4. 原件检测与最终文件复核共用上述后处理，日期保护仍生效。模型权重、配置和可信哈希未变化，没有重新训练模型。

## 原问题样例对比

使用此前线上 0.3.0 留存的原样例与实际输出作对照，再通过测试环境 HTTP 接口提交同一文件。全部为测试素材，不含真实病案。

| 项目 | 原线上 0.3.0 结果 | 修复后测试环境 |
| --- | --- | --- |
| 不存在的二维码 | 1 个大框，误遮正文 | 0 个，诊断、金额、说明保留 |
| 印章 | 1 个颜色框，另有重叠签名框 | 合并为 1 个 SEAL，来源保留 color 与 visual-model |
| 手写签名 | SIGNATURE 计数 2，包含误分类圆章 | 1 个 SIGNATURE，位于手写签名区域 |
| 最终文件视觉复核 | passed | passed，findings=[] |
| 日期冲突 | 0 | 0 |

注意：视觉残留复核只检查印章、签名是否仍可见，不会证明正文没有误遮。原线上样例虽然 passed，仍存在二维码误框；本次同时检查检测框、应保留区域和输出图片。

## 验证覆盖

- 完整测试：164 passed；两个既有告警（Starlette TestClient 弃用、超大图片防护测试）不影响通过。
- 独立容器 `redactx-visual-test`，镜像 `redactx:qr-visual-fix`，仅绑定 127.0.0.1:8091；6 GB / 6 CPU，独立数据目录，只读挂载模型。
- HTTP 五组样例：原问题样例、灰章、仅选 SEAL、仅选 SIGNATURE、加入真实二维码的样例。均符合类别和数量预期，视觉复核均 passed，疑似残留与日期冲突均为 0。真实二维码仍被遮盖。
- 原问题样例通过复核保存接口再次处理，最新视觉检查仍 passed。
- 单元回归包含正文伪候选、损坏内容的二维码、大尺寸二维码、灰/红双环圆章、手写开环、两个相互重叠的独立对象、同一 query 多类高分与复选框排除。
- 14 页合成回归：258 / 258 应遮项完全覆盖；106 项应保留内容误遮 0，多遮 0。低质量扫描和拍照样例各保留 1 处疑似残留提示，与历史验收状态一致，未消除这些提示或将其强改为通过。

## 结果与边界

已复现的正文二维码误框和双环圆章误分类在测试样例中修复。双环判据不适用于所有印章外观；破损章、矩形名章、复杂重叠以及定位图案严重损坏的二维码仍需业务样本复核。本次没有真实临床样本准确率结论，也不保证视觉模型全局不再混淆类别。

验收证据保留在本机 `local/qr-visual-fix/`，包括前后图片、各样例报告、接口验收汇总、14 页评估结果和独立测试数据。线上仍运行原正式版 0.3.0；是否升级由用户查看结果后另行决定。
